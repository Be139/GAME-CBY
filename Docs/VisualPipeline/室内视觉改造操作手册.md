# 室内视觉改造操作手册

写给接手室内视觉改造的 Agent。2026-10-31 由 Claude Code 在《已为您沟通》（HEARTH）的 Noah 房间、其余室内空间和大堂外街道实际做完后整理，文中数值都是用过的数值，可以直接抄。

**验收标准只有一个：和 Noah 的房间比。** 用户到目前只认可了这一间，其他空间还在调整中。工作顺序是：室内、大堂周边、机器人、城市。

做新房间前先通读一遍。第 4 节是审美规则，没有把握时照数值做，不要自由发挥。

工具都在 [tools/](tools/) 目录，第 17 节有清单。

## 1. 工作边界

用户定下的规则，优先于本手册其他内容：

- 只负责把画面做好。人物走位、穿模、挡路由用户自己检查和手动调整模型位置。
- 不做完整的行走路线测试，但**必须跑摆放检查**（`audit.cs`）：挡门、悬空、穿插都不能留。第一轮我没检查就批量摆放，查出 58 处错误，用户批评这是不该犯的错误。
- 摆错的模型还会把错误的光影烘进贴图，所以先过摆放检查再烘焙。
- 不在每个房间做完后检查其他空间。全部房间做完后统一看一次。
- 人物以后可能重做，不为人物改场景。
- 模型生成后直接用，不做额外的简化或人工验证。
- 速度和省 token 优先，但不能不看。每间房至少看平面图和 3–4 张视图。
- 复杂度向 Noah 房间看齐：约 2 件物件每平方米，墙上不留大片空白。
- 每个空间单独调，不要一套配方刷全部。模型可以复用，灯光和颜色不能照抄。
- 检查时必须把人物和机器人带上，只看墙不算数。
- 生成的是单独的物件。不要把整间房生成成一张图或一个模型放进 Unity。

不能动的东西：

| 物件 | 原因 |
|---|---|
| `Door_*`（尤其 `Door_2_Brown (4)`、17F03 的 `Door_2_Brown_02`、`Door_2_Brown (1)`） | 门铰链被脚本引用 |
| `InspectionTerminal_*`、`Lobby/TvUnitSet5` | 终端，有实体屏幕和固定相机 |
| `FamilyPhotoFrame_17F04` | 剧情道具，不是装饰画 |
| `Apartment_17F02/Cabinet`、`Cabinet (1)` | 被脚本引用，只能调颜色 |
| `HouseholdActors/*`、`Gameplay/*`、`Actor_*` | 演员和单元的交互体 |
| 旧壳体 `Floor17/unity3`、`unity4` 的碰撞体 | 玩家靠它们走路 |
| `Lighting_17F_ROOM1_DuskSample` | 被脚本引用，里面的灯可以关，物体不能删 |

其他规则：

- 替换掉的旧物件只隐藏（`SetActive(false)`），不删除。
- 不改 `Assets/Scripts`。本流程全部用一次性编辑脚本完成，不需要新增游戏脚本。
- 不提交 git，除非用户明确要求。
- 原始生成文件放项目外的 `E:/GAME-CBY_VisualBackup/generated`，只把用到的文件复制进 `Assets`。
- 每次开工前备份场景：把 `Assets/Scenes/SampleScene.unity` 复制到 `E:/GAME-CBY_VisualBackup/` 下带日期的目录。

## 3. 环境准备

### Unity

- 项目 `D:/UGit/GAME-CBY`，Unity 2022.3.61f1c1，URP 14.0.12，Forward，Linear，HDR。
- 场景只有一个：`Assets/Scenes/SampleScene.unity`。
- 控制 Unity 用项目自带的 CLI，必须在 Git Bash 里、项目根目录运行：

```bash
./Tools/Dev/unity-mcp.sh status
```

```bash
./Tools/Dev/unity-mcp.sh -t 120 -f json code execute -f script.cs
```

`code execute` 把文件内容当作一个方法体运行，用 `return` 返回文字。要点：

- 类型写全名，例如 `UnityEngine.Vector3`，文件里没有 `using`。
- 编译器是 codedom，只能用 lambda，不要用局部函数、字符串插值、`out var`、元组。
- 不能调用 `System.IO.File.Delete`，安全检查会拦下来。不要加 `--no-safety-checks`，换别的写法。
- 连接断开不代表没执行。大量重新导入时会断开，先等一分钟，再用只读脚本查结果，不要直接重跑写操作。

### Meshy

用 CLI，不用网页：

```bash
npm.cmd exec --yes --package=meshy-cli@0.4.0 -- meshy auth list
```

- 账号档案有 `default` 和 `production-02`，用 `auth use <档案名>` 切换。用量大时先花月度额度会早重置的账号。
- 查余额必须加 `MSYS_NO_PATHCONV=1`，否则 Git Bash 会把 `/balance` 改写成 Windows 路径：

```bash
MSYS_NO_PATHCONV=1 npm.cmd exec --yes --package=meshy-cli@0.4.0 -- meshy api GET /balance --format json
```

- 价格：`gpt-image-2` 图生图 12 积分，`smart-topology` 建模 15 积分，一件物件共 27 积分，单件约 1 分钟。
- API 产物只保留 3 天，生成后马上下载。
- 账号由用户登录，Agent 不输入密码、不注册账号。

Tripo 的条款不允许一人多账号，这里只用 Meshy。

### 运行工具

工具脚本里的路径已经指向 `Docs/VisualPipeline/tools`，临时文件写到它下面的 `_work`（已加入 `.gitignore`）。都在 Git Bash 里运行：

```bash
bash Docs/VisualPipeline/tools/vp_run.sh s_f02.cs
```

### 命令行的坑

- Bash 工具里 heredoc 内容带英文单引号会失败。提示词和脚本用文件写入工具写，不要写进 heredoc。
- Windows 控制台默认 GBK，打印中文或表情前加 `PYTHONIOENCODING=utf-8`。
- Python 用 `D:/Tools/Python/python.exe`，`python` 命令在这台机器上不可用。
- `E:\系统缓存` 含中文，这是 GPU 烘焙失败的原因（见第 12 节）。这是系统设置，不要改。

## 4. 审美规则

### Noah 的房间好在哪

| 要点 | Noah 房间的做法 | 用数值说 |
|---|---|---|
| 蓝调打底 | 环境和阴影都是蓝的，不是黑的 | 窗光和补光都用冷色，阴影保持可见的蓝 |
| 暖光只在灯边 | 只有一盏小台灯是暖的 | 暖灯范围 3–4 米，只照亮周围一两米 |
| 光有形状 | 月光穿过百叶，在墙上留下条纹 | 每个空间至少一种：百叶条纹、窗格、硬边光池 |
| 东西够多 | 书、玩具、画、拖鞋、背包 | 看得出住的是谁 |

做其他房间时犯过的错，不要重复：

- 用暖色补光把房间提亮。结果整间房一个暖色调，平，而且偏黄。**补光永远用冷色，暖色只给灯具。**
- 同一套配方刷所有空间。结果每间房都差不多，没有情绪。
- 只看墙不看人。人物不吃光照贴图，墙亮了人还是黑的。

### 风格

目标是风格化写实（stylized realism）里的低多边形、平涂色路线，对标 Virginia（2016）和 Last Stop（2021）。参考图在 `references/`，用户选的 7 张是 `user_ref_1–7`，用来喂模型的 3 张在 `references/style/`。

三句话概括：大形体、平颜色、靠灯光讲情绪。细节不来自贴图，来自光的形状。

### 明暗

每张画面都要能眯着眼分出三块：

- 一个亮区：叙事焦点所在，比如床头、餐桌、Lily 的台灯。
- 大面积中间调：墙和地，带蓝。
- 一块暗部：角落、走廊尽头。暗部不能死黑，要看得出形状和颜色。

Virginia 的暗部是饱和的深蓝紫，不是黑。整间房同样亮就是失败，大片死黑也是失败。

### 冷暖

- 夜晚和黄昏：环境冷、灯具暖。窗光 `7F97D6`，补光 `8FA6D8`，灯 `FFC48A`–`FFD9A8`。
- 早晨：太阳暖 `FFDDB0`，阴影里的补光偏冷 `DCE4F0`。
- 一个画面里只用这一组冷暖对比。粉紫霓虹只留在窗外，室内最多在天花板上留一点反光（强度 0.3–0.5）。

### 颜色

- 墙的明度保持中等。全白墙反光太强，光的形状就看不出来；纯黑墙吃光。
- 饱和度低：RGB 最大值和最小值之差不超过 70。
- 一个房间一个主色，加一个辅色，一个小面积点缀色。
- 地板比墙深一档，天花板比墙浅一档，踢脚线比墙浅（或在深色房间比墙深）。
- 不用纯白、纯黑、纯色。

### 材质

| 用途 | Smoothness | 贴图 |
|---|---|---|
| 墙 | 0.08 | 无，平涂 |
| 天花板 | 0.05 | 无 |
| 踢脚线、窗台 | 0.2 | 无 |
| 木地板 | 0.3–0.34 | `T_Planks.png`，用颜色调色 |
| 石材、水磨石 | 0.45–0.55 | `T_Tile.png`、`T_Terrazzo.png` |
| 生成的模型 | 0.14 | 模型自带的 `texture_0.png` |
| 地毯、布艺 | 0.05 | 图片 |
| 灯罩 | 0.2 | 加自发光 |

Metallic 一律 0。不用法线贴图。

### 陈设

分三层想：

1. 大件定结构：床、沙发、餐桌、柜子。尽量放在旧物件的位置，演员站位是围绕它们设计的。
2. 中件定生活：灯、植物、地毯、挂画、窗帘、百叶。
3. 小件讲人物：Noah 的积木、Lily 的画、猫碗、17F03 的日程表。每个房间至少要有一件只属于这家人的东西。

墙不能空着。用户选的参考图里墙上都有画框、架子或百叶的影子。

### 不要这样

- 不要有光没灯：看得到灯光的地方要看得到灯具，灯具要发光。
- 不要有灯具不发光：放了台灯就要接上 `Lit`。
- 不要塑料感：Smoothness 超过 0.55 的表面都不要。
- 不要用写实贴图的旧模型混在平涂模型里。留下来的旧物件要用 `Grade` 或 `Matte` 处理。
- 不要在图上出现文字、商标、人物。
- 不要让孩子的东西出现在没有孩子的家。17F02 原来散落的玩具已经隐藏。
- 不要把提示词改成写实风格。

## 6. 生成资产

### 物件模型

两步走：Meshy 出设计图，Tripo 建模。这样风格由参考图控制，模型质量更高。

| 步骤 | 工具 | 成本 |
|---|---|---|
| 设计图 | Meshy `gpt-image-2`，喂 3 张风格图 | 12 积分 |
| 建模 | Tripo High Detail，带贴图 | 40 积分，约 2 分钟 |
| 导出 | Tripo FBX ZIP | 免费 |

清单写进 `items_v2.txt`，每行 `id|面数|描述`：

```bash
bash Docs/VisualPipeline/tools/gen_refs_batch.sh items_v2.txt items_art2.txt
```

```bash
/d/Tools/Python/python.exe Docs/VisualPipeline/tools/tripo_batch.py list_v2.txt
```

`tripo_batch.py` 可以重复运行：已完成的跳过，已成功的模型不重复扣费，失败的重新提交。

**Tripo 的确认卡片。** Tripo 插件装在 Codex 里，付费任务要经过 60 秒确认卡片，插件文档明确写了 Agent 不能绕过。这个项目的用户明确授权“可以直接确认”，所以脚本调用卡片自己的 `confirm` 动作。换一个 Agent 或换一个用户时，要先取得同样的授权，否则不能这样做。

插件以 stdio 方式运行，入口是 `C:/CodexHome/plugins/cache/tripo-studio-plugins/tripo-studio-plugin/0.3.12/mcp/bootstrap.mjs`。登录状态由插件自己保存，不要读取或传递 Cookie。

要注意：

- 同时提交太多时有些任务会失败，重跑即可。少数物件一直失败（这次是玩具屋、小夜灯、储物篮），改用 Meshy 全流程。
- 下载只能到插件默认目录 `Documents/TripoStudio/downloads`，脚本再复制出来。
- FBX 要用 `texture_packaging: "zip"`，embedded 下载会被拒绝。

Meshy 全流程（27 积分）依然可用：`gen_item2.sh`。

提示词模板：

```text
Create one single object for a 3D game in the exact visual language of the reference images: very simple low-poly forms, large flat planes, soft small bevels, clean flat matte colours with only gentle gradients, muted warm-and-cool palette, no fabric texture, no wrinkle detail, no wood grain, no small clutter. Object: <描述>. Complete object fully visible, three-quarter view, plain neutral grey background, soft even light, no cast shadow, no text, no logo, no people.
```

描述怎么写：一句话，写形体、颜色、材质感，不写风格词。颜色写 `muted` 开头。

生成后拼一张缩略图看一遍。只重做明显错的，比如多了文字或物件断开。

### 地毯和挂画

`gen_img2.sh <id> <比例> "<提示词>"` 只生图，12 积分一张。地毯提示词写 `Top-down flat view ... filling the whole image edge to edge`，挂画写 `Flat stylized painting filling the whole image with no frame`，都写 `no text`。

### 换颜色不用重新生成

- `Tint`：`Put` 或 `Swap` 的最后一个参数是十六进制颜色，会乘到贴图上。适合变冷、变暖、变浅。
- `Retex`：贴图换色相，用于红被子换成蓝被子这种改变。`prep_rooms.py` 里的 `hue_variant` 生成变体贴图。

## 9. 改房间表面

### 坐标

全楼用同一套楼层坐标：原点世界坐标 `(-2312, 楼层高度, 595.6)`，旋转 `Y = -21.4°`。`x` 记作 u，`z` 记作 v，`y` 从地面算起。17 层地面 111.68，大堂地面 0.2。

所有根节点都用这套坐标，所以 `list_props.cs` 打印的坐标可以直接写进配置。

### 方法

旧壳体来自 `Assets/Art/Environment/SourceModels/unity3.fbx`，没有光照 UV，而且是一房一块网格，正好可以逐房替换。

`Copy` 的做法：

1. 把旧网格的顶点转到房间坐标，存成新的网格资源（`Rooms/shared/meshes/`）。
2. 用 `Unwrapping.GenerateSecondaryUVSet` 生成光照 UV。地面的 UV 按米算，这样地板贴图比例正确。
3. 法线用 `RecalculateNormals` 按三角形绕序重算。旧网格很多面的法线是反的，这就是旧场景里有些墙全黑的原因。绕序是对的，所以重算后就好了。
4. 旧渲染器改成 `ShadowsOnly`：看不见，但继续投影，碰撞体也继续工作。

这样门洞、窗洞、不规则户型都自动正确，不用手量也不用动碰撞。

## 10. 摆放

**不要用自动替换。** 早期的 `Swap` 把新模型放到旧物件的位置，结果书架和书桌叠在一起、东西挡门。现在每间房都先看平面图，再手写位置。

### 第一步：画平面图

```bash

```

```bash

```

每户一张图：白线是墙，红框是门，蓝框是新物件，灰框是保留的旧物件，橙框是机器人，粉点是演员，绿点是动画锚点。框内写名字和高度，`b` 是底部高度。

### 第二步：查模型比例

模型的长宽高比例差别很大，按高度缩放可能得到离谱的宽度。比如 `bookshelf` 是宽矮型，比例 1.00×0.62×0.30，按高 2 米缩放会变成 3.2 米宽。`plan_data.cs` 运行结果会列出全部模型比例（宽×高×深，最长边为 1）。

### 第三步：写配置

所有函数都读取真实表面，不要猜坐标：

| 函数 | 用途 | 参数 |

| `Back` | 背靠墙放在地上，射线找到真实墙面 | id、名字、基准、尺寸、u、v、墙的方向、颜色、是否加碰撞体 |

| `Old` | 取保留的旧物件当底座 | 名字 |
| `OnWall` | 贴墙挂件（钟、镜子、面板） | id、名字、基准、尺寸、u、底边高度、v、墙的方向、颜色 |

## 11. 灯光

### 规则

- **补光用冷色。** 需要提亮时加冷色 Baked 点光，高度 1.7 米。不要加暖色补光。
- **暖灯范围要小。** 台灯、落地灯范围 3–4 米，只照亮周围。
- **每个空间至少一种有形状的光。** 用 `Blinds` 做百叶，窗外放一盏 Mixed 聚光打条纹。
- Mixed 负责实时直射，一个空间 2–3 盏。其余 Baked。
- 人物和机器人靠光照探针（`ProbeGrid`），每个空间都要有，见第 14 节。
- 所有灯用 Soft 阴影。街道灯和大堂高位灯用无阴影。
- 灯具模型的 Cast Shadows 要关，否则灯被自己挡住。`Lit` 会自动关，并把灯具移出烘焙。
- 不要留旧的实时补光灯，它们没有阴影，会穿墙。`Lobby/Spot Light (9)` 下的 Point Light 按房间关掉（`LightsOff`）。
- 一个物体最多接收 8 盏灯。大面积的地面要切成小段，否则近处的灯被挤掉。

`Rect` 的朝向：窗在 +u 一侧用 −90，窗在 −u 一侧用 90，窗在 −v 一侧用 0，窗在 +v 一侧用 180。

窗洞位置用 `scan_openings.cs` 读出来，打印的就是洞口四角的楼层坐标，`y2.5` 无 `y0.9` 的是落地门，有 `y0.9` 的是窗。

### 发光灯具

```csharp
Lit(Put("floor_lamp", "Prop_FloorLamp", 'H', 1.6f, -1.85f, 0f, 2.55f, 0f, false, 0.4f, null), "floor_lamp", "FFD9A8", 1.4f);
```

有 `<id>_emit.png` 就只让那部分发光，没有就整个模型发光。`globalIlluminationFlags` 不要设成 `EmissiveIsBlack`，否则 URP 会把 `_EMISSION` 关掉。

## 14. 烘焙

### 必须一起烘焙

Unity 一次烘焙会替换全部光照贴图，所以每次都要把所有已改造的空间一起烘焙。`vp_bake_start.cs` 开头有空间列表，新增空间时加进去。

### 命令

```bash
bash Docs/VisualPipeline/tools/vp_bake2.sh 20 512
```

两个数字是每单位纹素和间接采样数。2026-11-06 起用这套（`vp_bake2_start.cs`）。旧的 `vp_bake.sh 20 256` 只留作对照：它出的墙面有斑块。

### 墙面马赛克和死黑（2026-11-06 查明）

0. **墙面纹素被烘焙器判为无效、再用邻近纹素填补，这是“马赛克”的根本原因。** 烘焙器从每个纹素发射光线，看到背面的比例超过 Backface Tolerance（默认 0.9 即要求 90% 命中正面）就判定该纹素无效，丢掉计算结果，再用旁边有效纹素的值向外填（dilation）。填出来的是一块块颜色均匀、边缘呈台阶状的区域：墙上部一排像城市天际线的锯齿、壁灯旁边的“小房子”形状、17F04 门上方的台阶，都是它。以前被大半径模糊抹成了斑块。修法：`lp_walls.cs` 建一个 Lightmap Parameters（`Rooms/shared/LP_Walls_KeepTexels.giparams`：Backface Tolerance 0，Pushoff 1 毫米），挂到所有 `Shell` 下的墙地天花上（96 个）。验证方法：把附近几盏灯临时改成纯红、纯绿等颜色（`light_tag.cs`），低采样烘一次；正常的灯光应该从灯向外平滑衰减，出现大块平涂、台阶边缘就是这个问题。
   排查中还加了 `bake_roof.cs` 的隐形屋顶（`BakeRoof_17F`、`BakeRoof_Lobby`，只投影、不占光照贴图），防止楼上不参与烘焙时天光从天花缝漏下来。它对这次的锯齿没有作用，但保留着无害。
1. **间接光采样不够。** 256 次采样加 `Filtering: Auto` 的半径 5 Gaussian，把噪点抹成 30–40 厘米的斑块，这就是墙上的“马赛克”。现在用 512 次采样，降噪用 OIDN（Intel Open Image Denoise，CPU 也能跑），之后只加半径 1 的 Gaussian。
2. **烘焙灯是硬阴影，贴墙的小灯还会掠射。** 76 盏烘焙灯的阴影半径都是 0，阴影边落在 7 厘米一个的纹素上，就成了锯齿方块。`q_fix.cs` 给了半径：补光 0.35，筒灯 0.05。壁灯、台灯这类离墙只有一掌宽的小灯，光几乎贴着墙面走，会把门框、画框的影子拉成一长串台阶状的形状（走廊壁灯旁、17F04 门口台灯上方最明显），`lamp_soft.cs` 把它们的阴影半径加到 0.5，并把走廊壁灯的烘焙光从离墙 0.25 米挪到 0.4 米。
3. **墙面实际纹素太少，这是方块状“马赛克”的主因。** 复制出的壳体墙是又长又窄的条带，自动生成的光照 UV 只占满 UV 方格的一小部分，所以实际密度远低于名义值：走廊墙按名义应有每米 26 个纹素，实测只有 14 个；护墙板只有 4.8 个，约 20 厘米一格，靠近壁灯时就是一块块的方格。名义密度不能信，要按三角形量 UV 面积。`q_fix.cs` 先把小物件（0.6 米以下）改用光照探针；`q_fix2.cs` 再按实测密度给 250 个表面重设 Scale In Lightmap：17 层大面每米 32 个，大堂 20 个，家具 18 个，单个物体不超过 300 万纹素。`wall_texel.cs` 可以从某个机位实测看到的表面密度。
4. **旧壳体和新墙重合。** 28 块旧壳体只投影不显示，和复制出的新墙完全重合，现在关掉了它们的渲染器，碰撞体照常。
5. **死黑是缺光，不是模型。** 17 层大厅原来只有天花灯，开口外的天光和招牌光进不来。`atmo_1106.cs` 在大厅开口处加了窗光（蓝紫天光，靠广告牌的一段加洋红），公寓窗光加强，17F04 加了广告牌的洋红溢光。新灯都在各空间的 `Atmos_1106` 组里，重跑会先删再建。

判断方法：Unity 官方建议先把 Filtering 设成 None 看原始噪点。斑块随采样数增加而变小，就是采样问题；不变，就是几何或漏光问题。

CLI 在烘焙结束时常报 500 或断开，这是保存大场景造成的。`vp_bake_finish.cs` 其实已经执行或可以安全重跑：用 `state_check.cs` 确认 `dirty=False`，探针数约 1,700，再看 `_work/bake_state.txt` 是否为空，不为空就重跑一次 `vp_bake_finish.cs`。

### 脚本做了什么

1. 保存场景。
2. 记录并清掉空间之外所有物体的 Contribute GI，烘焙后恢复。
3. 门的 Scale In Lightmap 设为 0、临时参与 GI：挡光，但不占贴图。
4. 调用 `Lightmapping.BakeAsync()`。不要用同步的 `Bake()`，会卡死 MCP 连接。
5. 结束后恢复，保存场景。

### 大坑

**GPU 烘焙要先换临时目录。** 系统临时目录 `E:\系统缓存` 含中文，GPU 烘焙器会失败：日志是 `Could not open file ... dep-*.d` 和 `Failed to render lightmap`，界面不报错，但贴图是空的。2026-11-06 起 `vp_bake3_start.cs` 只把 Unity 编辑器这个进程的 `TEMP`、`TMP` 指到项目里的 `Temp/gpu_bake_tmp`（纯英文路径，Unity 退出时清空），不改系统设置，然后用 Progressive GPU。RTX 3060 Laptop 上约每秒 2,000 万条光线，CPU 只有约 250 万条。日志出现 `GPU Progressive lightmapper will use OpenCL device` 就说明成功；显存不够时它会自动切到分块模式。

```bash
bash Docs/VisualPipeline/tools/vp_bake3.sh 20 512
```

**光照探针必须有。** 人物、机器人这些动态物体不吃光照贴图。没有探针时，它们只有深蓝环境光和少数 Mixed 灯，在亮的房间里就是一个黑影。每个空间用 `ProbeGrid` 铺一组探针，高度 0.5、1.5、2.5，间距约 1.6 米；大堂高度 0.6、2、5，间距 4 米。

场景里 `OutdoorProps` 的 13 棵树自带探针组，共 858 个探针，要一起烘焙。如果只烘焙树上的探针、室内没有，室内物体会去取室外的值，亮度全错。

**不要给生成模型开太小的 UV 间距。** Pack Margin 小于 48 时，柜子内侧的隐藏面会把脏色渗到外面，出现斑块。如果还有斑块，加一份 Lightmap Parameters：`backFaceTolerance 0.05`、`pushoff 0.012`。

### 时间

Noah 一间房：40 纹素、1024 采样，155 秒。六个空间一起：20 纹素、256 采样，约 10 分钟。这台机器上 CPU 烘焙的成本大致和纹素数乘采样数成正比。

2026-11-06 的新设置（按实测密度缩放后约 1,860 万纹素、512 采样）用 CPU 估计要 7 小时，用 GPU（`vp_bake3.sh`）约 5–6 分钟，出 3 张贴图：4096、2048、256。试错时可以先用 `vp_bake3.sh 20 128` 跑 3 分钟左右的低采样版。

| 物件朝反了 | 模型正面朝 +Z | 改 yaw，或用 `Auto` |
| 旧物件还在 | 名字在别的公寓下，比如 `Sofa_06_D` 在 17F02 下却摆在 17F01 | 临时切换 `apt` |
| 墙面大块斑驳，像马赛克 | 墙面纹素被判无效后用邻近值平涂填补，宽 Gaussian 再把它抹成斑 | 墙地天花挂 `LP_Walls_KeepTexels`（Backface Tolerance 0）；采样 512，降噪 OIDN，Gaussian 半径 1（第 14 节） |
| 墙上有台阶状、“小房子”状的平涂光块 | 同上，纹素无效后的填补 | 同上；用 `light_tag.cs` 给灯染色确认 |
| 阴影边缘是锯齿方块 | 烘焙灯阴影半径为 0，纹素太大 | 给烘焙灯阴影半径，抬高大面墙的 Scale In Lightmap |
| 大厅、走廊一片死黑 | 只有天花灯，窗外的光没有进来 | 在开口处放 Rectangle 烘焙窗光，靠招牌的一段加招牌颜色 |
| 天上有发光的线或点 | 远处的楼被雾遮住，楼上的发光物还亮着 | 城市装饰只放 600 米内，不做楼顶轮廓灯条 |
| 新加的东西出现在离楼很远的地方 | 楼的预制体带 270° 的 X 轴导入旋转 | 在水平坐标系里量楼的尺寸（见 `city_accents.cs`） |
| 用 `Room()` 改已摆好的房间 | `Room()` 会删掉整个空间重建，用户手调的位置会丢 | 只往现有根节点下加新组，参考 `atmo_1106.cs` 的 `UseRoot` |
