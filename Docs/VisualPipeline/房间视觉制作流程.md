# 房间视觉制作流程

2026-10-31，从 17F01 Noah 的房间总结。已被 [室内视觉改造操作手册](室内视觉改造操作手册.md) 取代，新房间请看手册，本文只保留 Noah 房间的做法记录。

## 基调

依据用户选定的 `references/` 7 张图和 Virginia、Last Stop：蓝调环境、暖色灯光、清晰的窗光形状、干净哑光的表面，霓虹只留在窗外。

模型要简单：大平面、小倒角、平涂色、没有布纹和木纹、少量杂物。

## 三层结构

| 层 | 内容 | 做法 |
|---|---|---|
| 房屋 | 墙、地、顶、门、终端 | 旧外壳保留，继续负责碰撞；房间内搭一层独立内壳，负责外观和烘焙 |
| 灯光 | 月光、灯具、窗口天光 | Mixed 灯负责实时直射光，Baked 灯负责柔和反弹光 |
| 物件 | 家具、玩具、挂画 | AI 生成，一件一个模型，单独摆放 |

要动、要交互的东西不走 AI，例如门、终端、演员和家用单元的交互体。

## 场景结构

每个房间一个根节点，例如 `Floor17/Apartment_17F01/VisualPass_NoahRoom`：

| 子节点 | 内容 |
|---|---|
| `Shell` | 内壳：地、顶、四面墙，窗洞和门洞留空 |
| `Trim` | 踢脚线、窗台 |
| `Blinds` | 百叶窗，每片单独倾斜 |
| `Props` | 生成的物件、地毯、被子 |
| `WallArt` | 墙上的画、夜色玻璃 |
| `Lights` | 灯光和反射探针 |

根节点朝向与房间墙面对齐，局部坐标 X 朝窗、Z 朝床头，地面高度为 0。被替换的旧物件只隐藏，不删除，需要时可以重新打开。

## 生成模型

1. 参考图用 `references/style/` 里的风格图，通过 Meshy 图生图生成灰底单件图（`gpt-image-2`，每张 12 积分）。
2. 用 `image-to-3d --input-task-id <图片任务> --model-type smart-topology --target-polycount <面数> --enable-pbr false --texture-resolution 2k` 建模（每件 15 积分，约 30 秒）。
3. 面数参考：床 1,200，书架 1,500，桌柜 900，椅子 600，小件 200–500。整间房约 9,000 面。

提示词开头固定写明：`very simple low-poly forms, large flat planes, soft small bevels, clean flat matte colours, no fabric texture, no wrinkle detail, no wood grain`。

## 导入 Unity

- 文件放 `Assets/Art/Generated/<房间>/<物件>/`，统一用 FBX。
- 模型导入：`Use File Scale` 关，Generate Lightmap UVs 开。
- 材质：URP Lit，贴图用 `texture_0.png`，Smoothness 0.14，Metallic 0。
- 生成模型的长边大约 1 个单位，摆放时按真实尺寸缩放，用模型自身包围盒对齐地面。
- 大件加 BoxCollider，小件不加。
- 全部标记 Contribute GI 和 Reflection Probe Static。

交互射线只认可交互物体，新碰撞体不会挡住按 E 交互，但会挡住玩家移动，摆放时要留出路线。

## 灯光

| 灯 | 类型 | 模式 | 作用 |
|---|---|---|---|
| `Light_Moon` | 聚光，放在窗外 | Mixed，软阴影 | 穿过百叶形成条纹 |
| `Light_TableLamp` | 聚光，放在灯罩内 | Mixed，软阴影 | 床头暖光 |
| `Bake_LampGlow` | 点光 | Baked | 灯周围的柔和暖色 |
| `Bake_WindowSky_*` | 面光，贴在窗洞内侧 | Baked | 窗口的蓝色天光 |
| `Bake_NeonBounce` | 聚光 | Baked | 窗外霓虹在天花板上的一点粉色 |
| `Probe_NoahRoom` | 反射探针 | Baked | 替代天空盒反射 |

- 灯具模型的 Cast Shadows 要关，否则灯被自己的模型挡住。
- 灯罩发光用单独的自发光贴图，`globalIlluminationFlags` 不要设成 `EmissiveIsBlack`，否则 URP 会关掉 `_EMISSION`。
- 百叶片向上倾斜约 26°，让月光穿过。

## 烘焙

只烘焙当前房间，不影响其他区域：

1. 保存场景。
2. 记录并清除房间外物体的 Contribute GI 标记。
3. 关掉场景里全部 Light Probe Group 和房间外的烘焙反射探针。
4. 在门洞放临时遮挡块（Scale In Lightmap 为 0），烘焙后删除。
5. 用 `Lightmapping.BakeAsync()` 启动，不要用同步的 `Bake()`，否则会卡住 MCP 连接。
6. 结束后恢复第 2、3 步，保存场景。

**用 CPU 烘焙器。** GPU 烘焙器在这台机器上会失败：系统临时目录 `E:\系统缓存` 含中文，日志是 `Could not open file ... dep-*.d` 和 `Failed to render lightmap`，画面没有报错但贴图是空的。

**不要留下烘焙过的光照探针。** `OutdoorProps` 下 13 棵树各自带一组 Light Probe Group（共 858 个探针）。只要它们被烘焙，全场约 15,500 个未烘焙物体都会改用这些探针，整座大楼的亮度都会变。所以烘焙时必须关掉，也不要新增探针组。

## 验收

- 从房间四个方向和俯视看一遍，不只看开场机位。
- 进 Play 走真实入口：`MinLoopFlowController.SetActiveReplayResident("17F01")`，再 `RequestReplayFromTerminal()`。
- 看运行时的演员姿势，编辑器里的姿势和实际不同。
- Console 不新增错误。

## 脚本

本流程没有新增或修改 `Assets` 里的脚本。一次性编辑脚本放在 `prototype/`，通过 `./Tools/Dev/unity-mcp.sh code execute -f` 运行。
